**رحلة العميل** (٦ مراحل): المحادثة ← ملف المشروع ← خارطة الطريق ← تحليل الاحتياجات ← المطابقة الذكية ← التوصيات وحجز الموعد.

**رحلة مقدّم الخدمة** (٤ مراحل، أُضيفت 2026-10-04): بوابة الاشتراك ← المحادثة ← ملف القدرات ← المطابقة العكسية ← صندوق الفرص.

**الربط بين الوجهين:** الجانبان يستخدمان **نفس دالة المطابقة على نفس الكتالوج**:
- عند إكمال مقدّم الخدمة لملفه، يُضاف إلى `PROVIDERS` — الكتالوج نفسه الذي تطابق عليه رحلة العميل.
- عند إكمال العميل لرحلته، يدخل مشروعه في بركة الفرص التي يراها مقدّم الخدمة.
- النسبة المئوية **متطابقة في الاتجاهين** — تم التحقق بـ ٢٠٬٠٠٠ تجربة عشوائية، صفر اختلاف.

## البنية التقنية للنموذج

ملف HTML واحد، بلا خادم وبلا مكتبات خارجية. كل المنطق مكتوب بـ JavaScript عادي داخل الملف.

```
index.html
├── <style>  هوية وَصلة البصرية (متغيرات CSS من لوحة الألوان)
├── <script> الكتلة ١ — رحلة العميل (~١٤٥ ألف حرف)
│   ├── WKB              قاعدة معرفة القطاعات والأنشطة الفرعية
│   ├── DIMS / DIMKEYS   أبعاد الاحتياج التسعة
│   ├── QUESTIONS        أسئلة المحادثة ١٢ سؤالاً
│   ├── classifyIdea()   تصنيف الفكرة من النص الحر
│   ├── computeNeeds()   بناء متجه الاحتياج ٠–١٠٠
│   ├── RSTEPS           مكتبة خطوات خارطة الطريق
│   ├── buildRoadmap()   اختيار وترتيب الخطوات
│   ├── PROVIDERS        ١٤ جهة (أسماء تجريبية)
│   ├── runMatching()    تشابه جيبي + ترجيح
│   └── window.__WASLA   الجسر إلى وحدة مقدّم الخدمة
└── <script> الكتلة ٢ — رحلة مقدّم الخدمة (~٢٨ ألف حرف)
    ├── POOL             ١٢ مشروعاً محلَّلاً (أسماء تجريبية)
    ├── PQ               أسئلة مقدّم الخدمة ٨ أسئلة
    ├── buildCaps()      بناء متجه القدرات
    ├── pairScore()      نفس معادلة المطابقة، بالاتجاه المعاكس
    └── registerProvider() يضيف الجهة إلى PROVIDERS المشترك
```

### الأبعاد التسعة (DIMS)
`funding` تمويل · `legal` تأسيس وتراخيص · `marketing` تسويق · `tech` بناء المنتج ·
`mentor` إرشاد · `space` مقر ومساحة · `finance` إدارة مالية · `team` فريق وتدريب · `ops` تشغيل ولوجستيات

### معادلة المطابقة (واحدة للاتجاهين)
```js
cos       = التشابه الجيبي بين متجه الاحتياج ومتجه القدرات
stageFit  = 1 إذا كانت الجهة تخدم مرحلة المشروع، وإلا 0.35
sectorFit = 1 إذا كان القطاع ضمن خبرتها، وإلا 0.30
cityFit   = 1 للمدينة نفسها · 0.70 إذا كانت تعمل عن بُعد · وإلا 0.35

raw = cos×0.60 + stageFit×0.18 + sectorFit×0.14 + cityFit×0.08
pct = clamp(round(raw × 100 / 0.985), 41, 98)
```
الأوزان قابلة للضبط في مكان واحد داخل `runMatching()` و `pairScore()` — **إذا غيّرت واحدة غيّر الأخرى**
وإلا انكسر تطابق الاتجاهين.

### كيف تعدّل النموذج
- **إضافة مقدّم خدمة:** أضف عنصراً إلى مصفوفة `PROVIDERS` بنفس شكل العناصر الموجودة (كل المفاتيح مطلوبة).
- **إضافة مشروع لصندوق الفرص:** أضف عنصراً إلى `POOL` في الكتلة الثانية.
- **تغيير أسئلة العميل:** `QUESTIONS` · **أسئلة مقدّم الخدمة:** `PQ`
- **تغيير الألوان:** متغيرات CSS في `:root` أعلى الملف.
- بعد أي تعديل: افتح الملف في المتصفح وجرّب الرحلتين كاملتين قبل الاعتماد عليه.
